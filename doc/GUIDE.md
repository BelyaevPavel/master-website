# 📖 Полное руководство по управлению сайтом

Добро пожаловать! Это руководство поможет вам самостоятельно обновлять информацию на вашем сайте без помощи программиста.

**Главная хорошая новость:** Ваш сайт теперь **«умный»**. В него встроена система автоматической проверки (валидации). Если вы случайно забудете запятую, поставите лишние кавычки или напишете слишком короткий отзыв, сайт **не сломается**, а просто напишет вам понятную ошибку в терминале и попросит исправить.

---

## 🎯 Введение: Как работает ваш сайт

```text
📁 Все тексты и данные → лежат в файлах JSON
📁 Все фотографии → лежат в папках images
📁 Когда вы меняете JSON → сайт автоматически обновляется после публикации
```

**Что вы сможете делать сами:**

- ✅ Менять телефон, адрес, email и координаты
- ✅ Обновлять цены, добавлять галереи и FAQ к услугам
- ✅ Добавлять новые услуги целиком
- ✅ Добавлять новые работы в портфолио (с фильтрацией по тегам)
- ✅ Публиковать отзывы клиентов
- ✅ Менять текст на странице «Обо мне»
- ✅ Редактировать блок статистики (цифры на главной)

**Что НЕ нужно делать:**

- ❌ Менять дизайн (это требует правок в коде)
- ❌ Трогать файлы с расширением `.astro`, `.css`, `.js`, `.ts` (если вы не уверены)

## 🛠️ Часть 1. Установка необходимых программ

### Шаг 1.1. Установите Node.js (Обязательно!)

Сайт работает на платформе Node.js. Без неё вы не сможете запустить сайт на компьютере.

1. Перейдите на [nodejs.org](https://nodejs.org/)
2. Скачайте версию **LTS** (не ниже 22.x).
3. Установите, нажимая «Далее».

### Шаг 1.2. Установите Visual Studio Code (редактор файлов)

1. Скачайте с [code.visualstudio.com](https://code.visualstudio.com/) и установите.
2. Откройте VS Code — это будет ваш главный инструмент.

### Шаг 1.3. Создайте аккаунт на GitHub и получите Токен

GitHub больше не принимает обычные пароли через терминал. Вам нужен **Personal Access Token (PAT)**.

1. Зарегистрируйтесь на [github.com](https://github.com/).
2. Зайдите в **Settings** (Настройки) → **Developer settings** (в самом низу слева) → **Personal access tokens** → **Tokens (classic)**.
3. Нажмите **Generate new token (classic)**.
4. Назовите его (например, `master-site`), поставьте галочку напротив **`repo`** и нажмите **Generate token**.
5. **Скопируйте токен** (длинный набор символов) и сохраните его в надёжном месте (лучше в менеджере паролей). **Он заменит вам пароль.**

> ⚠️ **Важно!** Никому не показывайте этот токен и не сохраняйте его в открытом виде в папке с сайтом. Если токен попадёт в чужие руки, злоумышленник сможет изменять ваш репозиторий.

### Шаг 1.4. Установите Git и GitHub Desktop (рекомендуется)

Для отправки изменений на сервер используется система контроля версий **Git**. Вы можете работать с ней двумя способами: через терминал (как описано в следующих частях) или через удобную программу с кнопками — **GitHub Desktop**. Даже если вы планируете использовать терминал, Git всё равно должен быть установлен, а GitHub Desktop сделает многие действия нагляднее.

1. **Установите сам Git**
   - Перейдите на [git-scm.com](https://git-scm.com/).
   - Скачайте версию для вашей операционной системы (Windows/macOS) и запустите установщик.
   - На всех шагах можно просто нажимать «Далее», оставляя настройки по умолчанию.

2. **Скачайте и установите GitHub Desktop**
   - Перейдите на [desktop.github.com](https://desktop.github.com/) и нажмите «Download».
   - Установите программу как обычное приложение.

3. **Войдите в свой аккаунт GitHub**
   - При первом запуске GitHub Desktop предложит «Sign in to GitHub.com» – нажмите и авторизуйтесь через браузер, используя логин и пароль от GitHub.
   - Если потребуется токен (см. Шаг 1.3), программа подскажет, как его применить. Обычно авторизация через браузер проходит автоматически и токен вводить вручную не нужно.

4. **Добавьте ваш репозиторий в программу**
   - Нажмите «Clone a repository from the Internet…» или в меню File → Clone repository.
   - Перейдите на вкладку URL, вставьте ссылку на ваш репозиторий (ту же, что вы использовали бы в VS Code) и выберите папку на компьютере.
   - Нажмите «Clone». Теперь все файлы сайта появятся в выбранной папке, а GitHub Desktop покажет текущее состояние.

**Как использовать GitHub Desktop вместо терминала:**

- Когда вы внесли изменения в JSON или картинки, GitHub Desktop сразу подсветит изменённые файлы в левой колонке.
- Чтобы сохранить (закоммитить) изменения, напишите краткое описание в поле «Summary» (внизу слева) и нажмите «Commit to main».
- Для отправки на сервер нажмите кнопку «Push origin» в верхней панели.
- Все команды из следующих частей (`git add .`, `git commit -m "..."`, `git push`) вы можете заменять этими тремя простыми действиями в GitHub Desktop.

> 💡 Даже если вы предпочитаете графический интерфейс, полезно один раз установить Git, потому что он всё равно нужен для работы VS Code и команд `npm install`, `npm run dev`.

## 📥 Часть 2. Как скачать и запустить сайт

### Шаг 2.1. Клонируйте репозиторий

1. В VS Code нажмите `Ctrl+Shift+P` (или `Cmd+Shift+P` на Mac).
2. Введите: `Git: Clone` и нажмите Enter.
3. Вставьте ссылку на ваш репозиторий (выдаётся разработчиком) и нажмите Enter.
4. Выберите папку на компьютере и нажмите **«Открыть»**.

### Шаг 2.2. Установите зависимости

1. В VS Code откройте терминал: `Ctrl+`` ` (или `View → Terminal`).
2. Введите команду:
   ```bash
   npm install
   ```
3. Подождите 1–2 минуты.

Чтобы видеть изменения сразу, не дожидаясь публикации в интернет:

1. В терминале введите:
   ```bash
   npm run dev -- --host
   ```
2. Пример вывода в консоль, если всё прошло хорошо:
   ```bash

    > astro dev --host
   ```

3. Откройте браузер и перейдите по адресу одному из этих адресов, например: **http://localhost:4321**
4. Теперь, когда вы сохраняете JSON-файлы, сайт в браузере будет обновляться автоматически!

> 💡 Если вы изменили фотографии, но в браузере они не обновились, откройте страницу в режиме инкогнито или выполните жёсткую перезагрузку (`Ctrl+Shift+R`).

## 📞 Часть 4. Как обновить контакты и мессенджеры

Откройте `src/data/contacts.json`.

```json
{
  "phone": "+79998887766",
  "whatsapp": "79998887766",
  "telegram": "master_service",
  "vk": "https://vk.me/master_service",
  "preferredMessenger": "telegram",
  "email": "info@master-website.ru",
  "city": "Белорецк",
  "city_dative_case": "Белорецке",
  "city_longitude": 58.24,
  "city_latitude": 53.58,
  "workingHours": "Ежедневно с 9:00 до 21:00",
  "socialMedia": {
    "vk": "https://vk.com/master_service",
    "instagram": "https://instagram.com/master_service"
  }
}
```

**Важные нюансы:**

1. **`preferredMessenger`**: Может быть `"whatsapp"`, `"telegram"` или `"vkontakte"`. От этого зависит цвет и иконка главной кнопки «Написать» на сайте.
2. **`vk` (в начале)**: Чтобы клиент сразу попал в диалог, используйте домен **`vk.me`** (например, `https://vk.me/master_service`).
3. **`city_dative_case`**: Город в предложном падеже (в ком? в чём?). Нужен для SEO-заголовков («Мастер по ремонту в _Белорецке_»).
4. **Координаты (`city_longitude`, `city_latitude`)**: Обратите внимание — сначала **долгота** (longitude), затем **широта** (latitude). Эти числа можно взять из Яндекс.Карт: обычно они отображаются в порядке «широта, долгота», поэтому просто поменяйте их местами. Например, для Белорецка координаты с карты: 53.58 (широта), 58.24 (долгота), значит пишем `"city_longitude": 58.24, "city_latitude": 53.58`. Это нужно для правильной микроразметки.

## 💰 Часть 5. Услуги, Галереи и SEO

Файл `src/data/services.json` содержит список всех услуг. Каждая услуга описана примерно так:

```json
{
  "id": "electric",
  "icon": "bi-lightning",
  "title": "Электромонтаж",
  "description": "Монтаж электропроводки, сборка щитов.",
  "priceFrom": 1500,
  "priceUnit": "руб. за точку",
  "features": ["Замена проводки", "Сборка щитов"],

  "detailedDescription": "Полное описание для страницы услуги...",
  "image": "@/images/services/electric-main.jpg",
  "gallery": ["@/images/services/electric-1.jpg", "@/images/services/electric-2.jpg"],
  "benefits": ["Опыт 10 лет", "Гарантия 3 года"],

  "serviceFaq": [
    {
      "question": "Сколько стоит замена проводки?",
      "answer": "Стоимость зависит от площади..."
    }
  ],
  "metaTitle": "Электромонтаж в Белорецке — цены, гарантия",
  "metaDescription": "Профессиональный электромонтаж. Гарантия 3 года."
}
```

### 🆕 Как добавить новую услугу

1. Откройте `services.json` в VS Code.
2. Найдите последнюю услугу и после её закрывающей фигурной скобки `}` поставьте запятую `,`.
3. Вставьте скопированный блок услуги (например, из примера выше) и измените все данные под новую услугу.
4. **Обязательно задайте уникальный `id`** (например, `"plumbing"`).
5. Подготовьте фотографии и положите их в папку `src/images/services/`.
6. В полях `image` и `gallery` пропишите пути к этим файлам, например: `"@/images/services/plumbing-main.jpg"`.

**Правила для изображений услуг:**

- Пути начинаются с `@/images/services/...`
- Можно использовать `.jpg`, `.png` или `.webp`.
- Файлы должны физически лежать в `src/images/services/`.

> 💡 Если вы укажете неверный путь, сборка сайта выдаст предупреждение `⚠️ Изображение не найдено`, но сайт продолжит работать (картинка просто не отобразится). Всегда проверяйте, что файлы на месте.

## 📸 Часть 6. Портфолио (До / После)

**Важное правило:** На **Главной странице** автоматически отображаются только **первые две работы** из списка в `portfolio.json`. Остальные попадают на страницу `/portfolio`, где клиенты могут фильтровать их по тегам.

### Шаг 6.1. Подготовьте фото

1. Сделайте фото «До» и «После».
2. Положите получившиеся файлы в `public/images/portfolio/`.

### Шаг 6.2. Добавьте запись в `portfolio.json`

Откройте файл и добавьте новый объект в массив.

```json
{
  "id": 3,
  "title": "Кухня с натяжным потолком",
  "description": "Двухуровневый потолок с подсветкой, 12м²",
  "beforeImage": "/images/portfolio/kitchen-before.jpg",
  "afterImage": "/images/portfolio/kitchen-after.jpg",
  "duration": "2 дня",
  "area": "12 м²",
  "tags": ["потолок", "кухня", "подсветка"]
}
```

**Нюансы:**

- **`id`** должен быть уникальным числом для каждой работы.
- Пути к фото начинаются строго с `/images/portfolio/`.
- Можно использовать `.jpg`, `.png` или `.webp`.
- **`area`** можно оставить `null` (без кавычек), если площади нет.
- **`tags`** — это кнопки-фильтры на странице портфолио. Пишите их с маленькой буквы, через запятую.

### 🆕 Как добавить новую работу: пошагово

1. Положите `.webp`-файлы в `public/images/portfolio/`.
2. Откройте `portfolio.json`.
3. Перед последней закрывающей квадратной скобкой `]` добавьте запятую (если там уже есть другие работы).
4. Вставьте новый блок и заполните его, начиная с `{ ... }`.
5. Убедитесь, что `id` не повторяется (можно просто увеличивать на 1).
6. Сохраните файл и запустите `npm run validate`.

## ⭐ Часть 7. Отзывы клиентов (Строгие правила!)

В файле `src/data/testimonials.json` система защиты от спама и некачественных отзывов очень строгая.

Пример записи:

```json
{
  "name": "Анна",
  "text": "Отличная работа! Плитка в ванной лежит идеально, швы ровные. Мастер аккуратный, убрал за собой.",
  "date": "2024-10-15",
  "photo": "/images/testimonials/anna.webp",
  "service": "Укладка плитки"
}
```

🚨 **Правила, за которыми следит робот:**

1. **Длина текста:** Минимум **20 символов**. Слишком короткие отзывы («Всё супер») сайт отклонит.
2. **Никаких двойных кавычек!** Внутри поля `text` **нельзя** использовать кавычки `"`. Если клиент написал: _Мастер сказал: «Отлично!»_, замените их на одинарные: _Мастер сказал: 'Отлично!'_. Иначе JSON сломается.
3. **Дата:** Строго в формате `ГГГГ-ММ-ДД` (например, `"2025-01-15"`).
4. **Фото:** Должно быть в `.webp` и лежать в `/images/testimonials/`. Если фото нет, пишите `null` (без кавычек).

### 🆕 Как добавить новый отзыв

1. Откройте `testimonials.json`.
2. Вставьте новый блок перед последней `]` (с запятой, если до него уже есть отзывы).
3. Заполните все поля, строго соблюдая правила выше.
4. Фото положите в `public/images/testimonials/` и пропишите путь.
5. Сохраните и запустите валидацию.

## ❓ Часть 8. FAQ (Вопросы и ответы)

Файл `src/data/faq.json` содержит общие вопросы, которые видны на главной и на странице FAQ.
🚨 **Правила валидации:**

1. В списке должно быть **минимум 3 вопроса**.
2. Поле `question` **обязано** заканчиваться знаком вопроса `?`.
3. Минимальная длина вопроса — 10 символов, ответа — 20 символов.

### 🆕 Как добавить новый вопрос

1. Откройте `faq.json`.
2. Добавьте новый объект в массив (по аналогии с портфолио).
3. Обязательно проверьте, что вопрос заканчивается на `?` и ответ достаточно подробный.

## 📝 Часть 9. Редактирование страницы «Обо мне» и статистики

### 📄 Страница «Обо мне» (`about.json`)

Файл `src/data/about.json` содержит ваш рассказ о себе, который отображается на отдельной странице. Структура примерно такая:

```json
{
  "title": "Обо мне",
  "text": "Я профессионально занимаюсь ремонтом уже 10 лет...",
  "additionalInfo": "Работаю с современными материалами и инструментом."
}
```

Вы можете смело редактировать поля `text` и `additionalInfo`, вставляя любые HTML-теги (например, `<br>` для переноса строки, `<ul><li>` для списков). Не удаляйте сами ключи `title` и `text` — сайт ожидает их наличие.

### 📊 Блок статистики (`stats.json`)

На главной странице выводятся цифры: количество выполненных проектов, лет опыта и т.п. Они берутся из `src/data/stats.json`.

```json
[
  { "label": "Выполненных проектов", "value": 420 },
  { "label": "Лет опыта", "value": 12 },
  { "label": "Гарантия (мес.)", "value": 36 }
]
```

Просто меняйте числа `value`. Можно добавлять новые строки, если сайт это поддерживает (обычно предусмотрено 3–4 показателя). Если добавили лишнее — просто удалите.

## 🧠 Часть 10. Ваш главный помощник: Команда `validate`

Перед тем как публиковать изменения, **всегда запускайте проверку**.

1. Откройте терминал в VS Code.
2. Введите:
   ```bash
   npm run validate
   ```

**Если вы всё сделали правильно, вы увидите примерно такой радостный вывод:**

```
🛡️  Начинаю проверку JSON-файлов...
────────────────────────────────────────────────────────
  ✅ 📞 Контакты (contacts.json) — OK
  ✅ 🔧 Услуги (services.json) — OK
  ✅ 📸 Портфолио (portfolio.json) — OK
  ✅ ⭐ Отзывы (testimonials.json) — OK
  ✅ ❓ FAQ (faq.json) — OK
  ✅ 📊 Статистика (stats.json) — OK
  ✅ 📄 Обо мне (about.json) — OK
────────────────────────────────────────────────────────
  🟢 Все JSON-файлы валидны! (0 предупреждений)
```

**Если допущена ошибка, терминал укажет конкретное место и описание:**

```
❌ В тексте отзыва не должно быть кавычек " (используйте одинарные ')
❌ Вопрос должен заканчиваться знаком вопроса "?"
❌ Путь должен начинаться с /images/portfolio/
```

Просто прочитайте ошибку, найдите указанное место в JSON и исправьте!

> 🔁 **Совет:** После внесения правок снова запустите `npm run validate`. Только когда увидите все зелёные галочки, переходите к публикации.

## 🚀 Часть 11. Как опубликовать изменения (Деплой)

Когда `npm run validate` пройден успешно:

---

### Шаг 11.1. Отправьте изменения на сервер (выберите удобный способ)

#### Вариант А: Через терминал

В терминале VS Code выполните по очереди:

```bash
# 1. Добавить все изменения
git add .

# 2. Сохранить с комментарием
git commit -m "Обновил контакты и добавил новую услугу"

# 3. Отправить на сервер
git push
```

_При запросе логина и пароля:_

- **Username:** ваш логин на GitHub
- **Password:** вставьте ваш **Personal Access Token** (из Части 1.3), а не пароль от сайта!

#### Вариант Б: Через GitHub Desktop (проще и нагляднее)

1. Откройте **GitHub Desktop**. В левой колонке вы сразу увидите все файлы, которые вы изменили (они будут отмечены галочками).
2. Убедитесь, что стоят галочки только у тех файлов, которые вы действительно хотите отправить (обычно это все изменённые JSON и новые картинки).
3. Внизу слева, в поле **«Summary (обязательно)»**, впишите краткое описание сделанного, например: _«Обновил контакты и добавил новую услугу»_.
4. Нажмите кнопку **«Commit to main»** (или «Commit to master», зависит от названия ветки). Это сохранит ваши изменения локально.
5. В верхней панели появится кнопка **«Push origin»** (или **«Push»**). Нажмите её — данные улетят на GitHub, и запустится автоматическая сборка сайта.

> 💡 Если кнопка «Push origin» неактивна, возможно, GitHub Desktop ещё не закончил проверку. Подождите пару секунд или нажмите **«Fetch origin»**, чтобы синхронизироваться.

---

### Шаг 11.2. Дождитесь сборки

1. Зайдите на страницу вашего репозитория на GitHub.
2. Перейдите во вкладку **«Actions»**.
3. Вы увидите процесс сборки. Если появилась **зелёная галочка** — сайт обновился в интернете через 1–2 минуты.

> ⚠️ Если сборка завершилась красным крестиком, нажмите на неё и прочитайте логи. Чаще всего ошибка в данных (например, забыли запятую). Исправьте JSON и снова выполните действия из 11.1. Если ошибка не ясна, лучше обратитесь к разработчику, а не экспериментируйте с откатами.

### 🛡️ Безопасное восстановление предыдущей версии

Если вы понимаете, что последнее изменение что-то сломало, самый безопасный способ — отменить последний коммит:

```bash
git revert HEAD
git push
```

Эта команда создаст новый коммит, который отменяет предыдущий, не удаляя историю. Если вы хотите отменить несколько коммитов или не уверены, свяжитесь с разработчиком.

## 🔄 Часть 14. Рабочий процесс (Идеальный сценарий)

1. Сделать фото, конвертировать в WebP (для портфолио), положить в нужную папку (`public/images/...` или `src/images/...`).
2. Открыть нужный JSON, добавить или изменить данные.
3. Сохранить (`Ctrl+S`).
4. Запустить проверку: `npm run validate`.
5. Если есть ошибки → исправить → повторить шаг 4.
6. Если всё чисто → запустить локальный просмотр `npm run dev`, визуально проверить.
7. Выполнить действия из пункта 11.1.
8. Проверить вкладку Actions на GitHub, дождаться зелёной галочки.

## 🆘 Если что-то пошло не так

- **Не отображаются новые фото** → откройте сайт в режиме инкогнито или нажмите Ctrl+Shift+R.
- **Сборка упала с ошибкой** → откройте логи сборки, скорее всего там подсветится строка с проблемным JSON. Исправьте и запушьте снова.
- **Случайно запушили неверные данные** → используйте `git revert HEAD`, чтобы безопасно отменить последний коммит.
- **Что-то непонятно или ошибка выглядит магической** → не гадайте, сделайте скриншот и отправьте разработчику. Вместе разберётесь быстрее.

### 💾 Регулярное резервное копирование

Чтобы никогда не потерять важную информацию, раз в месяц (или перед большими правками) копируйте папки `src/data` и `public/images` в облако или на флешку. Тогда даже при любой неполадке вы сможете восстановить все тексты и картинки.
